- **Toolchain** (ADR-0002):
  - an ESM package on Node 24 with exact pins (`.npmrc` `save-exact`)
  - TypeScript 7.0.2 (`tsc` builds `src/` to `dist/`; `tsconfig.build.json` leaves the tests out)

- **Config:** `src/config.ts` `loadConfig(env)` reads `CATALOG_API_URL` (default `http://localhost:3100`) and `CATALOG_API_KEY`.
  - It collects every problem and throws one error. Messages name the variable, never its value.
  - It rejects a key that isn't visible ASCII or is shorter than 32 characters, and a URL with credentials, a query or a fragment.
  - 20 tests. `.env.example` holds the public read key.
- **The catalogue stack** (ADR-0003): `docker-compose.yml`, project `catalog-agent`.
  - It builds catalog-api, its `migrate` target and search-service from `https://github.com/AbanobNageh/product-catalog.git#v1.1.0:services/…`.
  - The other settings are copied from that tag.
  - Images are named `catalog-agent-*:v1.1.0`; only catalog-api is published, on 3100.
- **CI:** `.github/workflows/ci.yml` runs `npm ci`, lint, typecheck, format check, test and build on pull requests, `main` and `v*` tags. It has `contents: read` and no secrets.

- **ADR-0001, ADR-0002 and ADR-0003,** accepted at this close.

  - MCP SDK v2 2.4.0, TypeScript 7.0.2, Vitest 5.0.5, and this repo's own Compose file building from git, all as recommended.

  - `.mcp.json` and the SDK install move to M2.
  - The user removed product-catalog's kind clusters to free memory.
  - `.claude/settings.json` stays as it is: for a showcase, prefix rules as a backstop are acceptable.

- **The AI's rulings during the build** (the plan's ledger):
  - config messages never echo a value, not even the URL
  - a separate build tsconfig
  - tests next to the code
  - `up -d --wait` in the docs
  - no Prettier on Markdown
  - no Dashboards profile

## Review findings and corrections
- **The fresh reviewer** (a separate AI agent, read-only, using the live stack) verified all 8 Review Focus items itself and found 2 Important and 11 Minor issues. Every finding and its re-grade is in the plan's "Fresh review" section. The ones that mattered:
  1. **The AI missed a key-leak path that product-catalog had already closed.** `loadConfig` accepted keys with spaces, line breaks or non-ASCII characters, and URLs with `user:pw@`. Node's `fetch` repeats those in its error message, so M1's client could have logged the key. Fixed test-first with product-catalog's rule.
  2. **ADR-0001 and `ai-workflow.md` overclaimed what the permission rules enforce.** Prefix rules miss variants (`git -C . push`), and nothing covered product-catalog. The docs now call them a backstop. The user decided not to add more rules.
  3. **A spec inaccuracy:** list items from `GET /products` do carry `version`, contrary to what §3.2 says. Checked live; it's an M2/M3 question in STATUS.
  4. Smaller fixes:
     - zod was installed against ADR-0002's own "install when first used" rule (removed)
     - "24 milestones" (it was 23)
     - the Compose header's start command
     - `engines` allowed Node 25, which Vitest doesn't support
     - CI ran twice on pull requests
     - `close-milestone` (inherited from product-catalog) committed the close before its STATUS tick and log line
- **The AI's own mistakes, caught before the review:**
  - its first config tests contradicted each other: one expected the bad URL echoed, the other forbade it
  - it left an unused YAML anchor in the Compose file
  - it wrote a muddled verify step in the plan
  - it drafted the start command without `--wait`; a live test showed an empty reply right after `up -d`
- **The user** reviewed the tour and the files and asked for no changes.
