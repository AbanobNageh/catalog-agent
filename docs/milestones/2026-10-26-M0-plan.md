# M0 Scaffold: Plan

**Goal:** an empty but complete repo. The AI context system, a pinned TypeScript toolchain where `npm test` runs, config from env vars, a Compose stack that runs a seeded catalog-api `v1.1.0` on :3100, and CI.

**Spec:** `REQUIREMENTS.md` §2 (steps 2 and 4–9) and the M0 row of §7. Design: [ADR-0001](../adr/0001-tiered-ai-context-system.md), [ADR-0002](../adr/0002-toolchain-version-pins.md), [ADR-0003](../adr/0003-catalog-stack-from-git-tag.md) (Proposed while planning; accepted at the close).

**The user's choices (2026-10-26):** `REQUIREMENTS.md` stays the spec, unsplit; ADRs are numbered from 0001 in this repo; this docs work is the start of M0; MCP SDK v2 2.4.0; TypeScript 7.0.2; Vitest 5.0.5; this repo's own Compose file, building from the git tag.

## Global constraints
- **Nothing is committed until the close,** and then only after the user's yes. Suggested messages are given per task, and each ends with the co-author trailer.
- **No MCP server code in M0.** The SDK packages are installed in M2 (ADR-0002).
- **product-catalog is read, never changed:** no edits, and no stopping or deleting its stack or clusters without the user's go-ahead.
- **Every command that goes into `AGENTS.md` is run first,** in PowerShell 5.1 where it's a PowerShell command.
- **No key value in any error message, log line or committed file,** except the Compose dev keys, which are public and marked as not secret.

## Review Focus
1. **Image and volume names can't collide with product-catalog's.** `docker images` before and after the first build: `catalog-api:0.2.0`, `catalog-api-migrate:0.2.0` and `search-service:0.2.0` (which product-catalog's kind clusters load) keep their image IDs. Volumes are `catalog-agent_*`.
2. **Only catalog-api is published, on 3100.** `docker compose ps` shows no other host port; 3000, 5432, 6379 and 9200 stay free.
3. **The stack really is `v1.1.0`:** the build contexts name the tag, and a keyed `GET /products/search?maxStock=5&sort=stock_asc` works, which needs 5.1's `maxStock`. Read access needs the read key (401 without a key) and the version reported by `/healthz` is `0.2.0`.
4. **The copied Compose settings match `v1.1.0`:** `action.auto_create_index`, the healthchecks, the `depends_on` conditions and the migrate job, compared line by line with `git show v1.1.0:docker-compose.yml`.
5. **The stdout rule is enforced:** a `console.log` (and `console.info`/`console.debug`, which also write to stdout) in `src/` fails `npm run lint`; `console.error` and `console.warn` (stderr) pass.
6. **`loadConfig` reports every problem at once and never echoes the key.** A test with a bad URL and a missing key gets both messages in one error, and no message contains the key's value.
7. **Nothing secret can be committed:** `.env` and `traces/` are ignored (`git check-ignore`), `.env.example` holds only the public dev keys.
8. **TypeScript 7 really works with this toolchain:** `tsc` (build and `--noEmit`), type-aware oxlint and Vitest all run on the scaffold. If not, fall back to 6.0.3 and amend ADR-0002 before the close.

## Open questions (answered 2026-10-26)

### Ledger of rulings (the AI's calls during the build)
1. **Config errors never echo a value,** not even the URL (product-catalog's `loadConfig` echoes it). A URL can carry credentials, and a key pasted into the wrong variable would otherwise be printed. Found while writing the tests: the first draft's two tests contradicted each other.
2. **A separate `tsconfig.build.json`** (excludes `*.test.ts`), so `npm run typecheck` still covers the tests that live next to the code in `src/`.
3. **Tests live next to the code** (`src/**/*.test.ts`), so `lint` covers `src/` only; there is no `test/` folder.
4. **`docker compose up -d --wait`** in `AGENTS.md` instead of plain `up -d`, after the empty reply in Task 4.
5. **Prettier formats code and config but not `*.md`,** which has long lines and tables formatted by hand. The only change it made to `docker-compose.yml` was one line wrap.
6. **No OpenSearch Dashboards profile** in this repo's Compose file (ADR-0003).

### Fresh review (2026-10-26): findings and re-grades
A separate agent, read-only, reviewed the whole uncommitted tree against `REQUIREMENTS.md` and this plan, using the live stack. It verified all 8 Review Focus items itself and found 2 Important and 11 Minor issues, with no Critical ones. Its verdict: ready once the two Important ones are fixed.
1. **Important, kept Important, fixed test-first:** `loadConfig` accepted a key with spaces, CR/LF or non-ASCII characters, and a URL with credentials, a query or a fragment. Node's `fetch` repeats such a header value or URL in its error, so M1's client could have leaked the key into a log or a tool result. Now rejected, with product-catalog's rule (visible ASCII, at least 32 characters); 10 new tests, seen failing first.
2. **Important, kept Important:** the `.claude/settings.json` ask rules miss parts of §9's list. Nothing covers touching product-catalog (its `kind delete*` rule was dropped), prefix rules miss variants like `git -C . push` or `docker compose -f … down -v`, and `gh api` isn't covered. ADR-0001 and `ai-workflow.md` overclaimed: both now say the rules are a backstop for the usual forms, not a boundary. **The settings file itself is left for the user,** because changing permission rules is the user's call. The user's ruling (2026-10-26): leave it as it is; for a showcase project, prefix rules as a backstop are acceptable.
3. Minor, fixed: zod was installed but unused; removed until M2.
4. Minor, fixed: product-catalog ran 23 milestones, not 24.
5. Minor, fixed: the Compose header now gives `--build` only for the first start and `up -d --wait` after that; `AGENTS.md` matches.
6. Minor, fixed: `engines` is `^24.0.0` (Vitest 5 doesn't support Node 25); ADR-0002 says why.
7. Minor, carried to M1: integration tests need their own name pattern and Vitest project, so `npm test` and CI don't need the stack, and test helpers must stay out of `dist/`.
8. Minor, fixed: in `close-milestone`, the STATUS tick and the log line now go into the `docs: close` commit, and the tick can take a commit range. Flagged for the user's Task 1 review, since it's their file.
